# محمّل الفيديو (VidGrab) — تطبيق أندرويد لتنزيل الفيديو والصوت

تطبيق أندرويد كامل مكتوب بلغة Kotlin وواجهة Jetpack Compose. تلصق رابط فيديو أو قائمة تشغيل من يوتيوب أو فيسبوك أو إنستغرام أو تويتر (X) أو تيك توك أو أي موقع من أكثر من 1000 موقع مدعوم، فيحلّله ويعرض لك الجودات المتاحة ثم ينزّله مع شريط تقدم وسرعة لحظية وإمكانية الإيقاف المؤقت والاستئناف.

ويحتوي أيضاً على **متصفح داخلي**: تتصفح أي موقع، وبمجرد **تشغيل** أي فيديو يظهر زر «تحميل الفيديو» فتختار الجودة وتحمّل دون أن تغادر الصفحة.

## المزايا

| المجال | ما يقدّمه التطبيق |
|---|---|
| إدخال الرابط | لصق يدوي، أو **مشاركة** الرابط من تطبيق يوتيوب/فيسبوك/إنستغرام مباشرة إلى التطبيق، أو اكتشاف رابط في الحافظة (Clipboard) مع اقتراح استخدامه |
| المتصفح الداخلي | متصفح كامل: تبويبات متعددة (حتى 12) تُحفظ بين مرات التشغيل، وشريط عنوان بالبحث واقتراحات من الإشارات المرجعية والسجل، وستة محركات بحث (Google وBing وDuckDuckGo وYandex وBrave وEcosia)، وصفحة أولى باختصارات المواقع، وإشارات مرجعية وسجل تصفح، وبحث داخل الصفحة، ووضع «موقع سطح المكتب»، وتسريع الفيديو (حتى 3×)، وملء الشاشة وصورة داخل صورة (PiP)، وحاجب إعلانات ومتتبعات، وقائمة الضغط المطوّل على الروابط والصور، وتنزيل الملفات العادية (PDF وZIP وغيرها) عبر مدير التنزيلات في النظام، وزر مسح بيانات التصفح |
| اكتشاف الفيديو | بمجرد تشغيل فيديو أو صوت في أي صفحة يظهر زر **تحميل الفيديو** تلقائياً، ويفتح ورقة بالخيارات المكتشفة (فيديو الصفحة، المشغّل المضمّن، أو ملف/بثّ مباشر) مع اختيار الجودة والتحميل من نفس الورقة |
| تسجيل الدخول | سجّل الدخول إلى إنستغرام أو فيسبوك أو X من المتصفح نفسه فتُستخدم جلستك تلقائياً لتنزيل ما يتطلب تسجيل الدخول (لا تُرسل كوكيز يوتيوب وجوجل أبداً) |
| المعاينة | صورة مصغّرة، العنوان، القناة، المدة، اسم الموقع |
| الجودة | اختيار الدقة (من 144p إلى 4K حسب المتاح) مع **الحجم التقديري** لكل دقة، أو «الأفضل» |
| الصوت فقط | MP3 أو M4A أو OPUS، وجودة 128 / 192 / 256 / 320 kbps |
| قوائم التشغيل | عرض كل المقاطع مع **تحديد الكل أو بعضها**، وإذا كان الرابط فيديو داخل قائمة يعرض زر «تحميل القائمة كاملة» |
| التقدم | شريط تقدم، النسبة، الحجم، **السرعة اللحظية**، الوقت المتبقي (ETA) |
| التحكم | إيقاف مؤقت، استئناف، إلغاء، إعادة المحاولة، «إيقاف الكل / استئناف الكل» |
| الطابور | من 1 إلى 5 تنزيلات متزامنة، تنزيل عبر Wi-Fi فقط، حد أقصى للسرعة، عدد الاتصالات المتوازية لكل تنزيل |
| الخلفية | خدمة مقدمة (Foreground Service) تُبقي التنزيل شغّالاً مع إغلاق الشاشة، وإشعار تقدم فيه زر «إيقاف الكل»، وإشعار عند الاكتمال يفتح الملف |
| الحفظ | `Movies/VidGrab` و `Music/VidGrab` (تظهر في المعرض) أو **أي مجلد تختاره**؛ مع فتح الملف أو مشاركته أو حذفه |
| الملفات | تضمين العنوان والمعلومات، تضمين صورة الغلاف، تضمين الترجمة (Subtitles) |
| الحسابات | استيراد `cookies.txt` للمقاطع الخاصة أو المقيّدة بالعمر أو منشورات إنستغرام/فيسبوك |
| المظهر | فاتح/داكن/حسب النظام، ألوان ديناميكية (أندرويد 12+)، واجهة **عربية (RTL) وإنجليزية** مع تبديل اللغة من داخل التطبيق |
| الصيانة | تحديث yt-dlp تلقائياً كل 12 ساعة أو يدوياً (قناة Stable أو Nightly) مع **التحقق من بصمة SHA-256** |

## كيف يعمل (ولماذا بُني بهذه الطريقة)

| المكوّن | الدور |
|---|---|
| yt-dlp | يستخرج الروابط ويحمّل من المواقع؛ يعمل داخل التطبيق نفسه عبر Chaquopy مع Python 3.13 |
| QuickJS-ng (`libqjs.so`) | محرّك JavaScript صغير يحتاجه yt-dlp لحل «تحديات» يوتيوب، وإلا تفشل أغلب مقاطع يوتيوب |
| FFmpeg | دمج مسار الفيديو مع مسار الصوت (يوتيوب يفصلهما)، وتحويل MP3، وتضمين البيانات |
| `vidgrab_engine.py` | جسر صغير بين Kotlin وyt-dlp؛ كل دواله تأخذ وتُرجع JSON، والتقدم يُقرأ بالاستعلام الدوري |
| `DownloadManager` | الطابور والإيقاف والاستئناف وحفظ القائمة وإشعارات التقدم |
| `BrowserController` / `BrowserTab` | المتحكّم يدير التبويبات والتبويب النشط والشاشة الكاملة؛ وكل تبويب `BrowserTab` له WebView خاص وكاشف JavaScript وقائمة الفيديوهات المكتشفة وحاجب الإعلانات |
| `BrowserStore` | الإشارات المرجعية والسجل (800 صفحة كحد أقصى) وعناوين التبويبات المفتوحة، تُحفظ في ملف `browser.json` |

**الإيقاف المؤقت والاستئناف:** الإيقاف يوقف yt-dlp ويترك الملفات الجزئية (`.part`) في مجلد مؤقت خاص بكل تنزيل، والاستئناف يشغّل التنزيل نفسه من جديد في المجلد ذاته فيكمل yt-dlp من حيث توقف (HTTP Range). تحققت من ذلك فعلياً: الملف الناتج مطابق للأصل بايتاً ببايت.

**المتصفح الداخلي: كيف يكتشف الفيديو؟** بثلاث طرق تعمل معاً، ولا يُنزَّل شيء إلا بعد أن تضغط أنت:
1. **أحداث التشغيل:** سكربت صغير يُحقن في كل إطار من الصفحة (حتى المشغّلات المضمّنة) يرصد لحظة بدء تشغيل أي عنصر `video` أو `audio` ويتجاهل الفيديوهات الزخرفية (القصيرة جداً أو الصامتة المكرَّرة).
2. **عنوان الصفحة نفسه:** يُقدَّم إلى yt-dlp الذي يفهم يوتيوب وفيسبوك وإنستغرام وX وتيك توك وفيميو وغيرها ويختار أعلى جودة مع الصوت. ولا يُعرض هذا الخيار في الصفحات التي ليست صفحة فيديو واحد (مثل الصفحة الرئيسية ليوتيوب التي تشغّل معاينات).
3. **طلبات الشبكة:** أي ملف `mp4` أو `webm` أو `mp3` أو بثّ `m3u8` (HLS) أو `mpd` (DASH) تحمّله الصفحة يظهر كخيار مباشر، وتُرسل معه ترويسة Referer والكوكيز الخاصة بالموقع لأن كثيراً من الخوادم تشترطها. وهذه الطريقة تنقذك في المواقع الصغيرة ذات المشغّلات المخصصة.

إن لم يظهر الزر في صفحة ما، فمن قائمة النقاط الثلاث اختر «تحميل فيديو هذه الصفحة»؛ وإن كنت تضغط على رابط لملف فيديو مباشر فتُعرض الورقة تلقائياً.

**لماذا لم أستخدم مكتبة youtubedl-android الشائعة؟** لأن آخر إصدار منها (0.17.2، نوفمبر 2024) يضمّن Python 3.8، بينما yt-dlp الحالي يتطلب Python 3.10 فما فوق، ويحتاج يوتيوب إلى محرّك JavaScript خارجي. لذلك يضمّن هذا المشروع Python 3.13 وQuickJS بنفسه، ويثبّت yt-dlp الرسمي (نسخة واحدة تحوي yt-dlp وyt-dlp-ejs) في تخزين التطبيق، ومعه نسخة داخل الـ APK تعمل بلا إنترنت أول مرة.

## بناء ملف APK

> لا يمكن لتطبيق أندرويد أن يُبنى بدون Android SDK؛ اختر إحدى الطرق التالية.

### الطريقة 1: GitHub Actions (الأسهل، بدون تثبيت أي شيء)
1. أنشئ مستودعاً (Repository) على GitHub وارفع إليه محتويات هذا المجلد.
2. افتح تبويب **Actions** ثم **Build APK** ثم **Run workflow** (ويعمل تلقائياً عند كل push).
3. بعد 10 إلى 20 دقيقة افتح التشغيل وحمّل **Artifacts → VidGrab-apk**؛ بداخله ملف `app-release.apk`.
4. انقله إلى الهاتف وثبّته (يجب السماح بالتثبيت من مصادر غير معروفة).

### الطريقة 2: Android Studio
- المتطلبات: Android Studio حديث (Narwhal 2025.1.3 أو أحدث)، JDK 17 أو أحدث (المرفق مع Studio يكفي)، واتصال بالإنترنت لتنزيل الاعتماديات.
- اختياري لكن يسرّع إقلاع التطبيق: تثبيت **Python 3.13** على حاسوبك (Chaquopy يستخدمه لتجميع الكود مسبقاً)؛ وبدونه يستمر البناء مع تحذير.
- الخطوات: **Open** ثم اختر هذا المجلد ثم انتظر **Gradle Sync** ثم وصّل الهاتف (USB debugging) واضغط **Run**، أو **Build → Build APK(s)**.

### الطريقة 3: سطر الأوامر
```
./gradlew assembleRelease
```
الناتج: `app/build/outputs/apk/release/app-release.apk` (موقَّع بمفتاح التطوير فيُثبَّت مباشرة).

**المعالجات (ABI):** يُبنى افتراضياً لـ `arm64-v8a` (كل الهواتف الحديثة). لتشغيله في محاكي الحاسوب أضف `-Pvidgrab.abis=arm64-v8a,x86_64`. (Python 3.13 يدعم 64-بت فقط.)

### إذا فشل البناء
رسالة «Compilation error. See log for more details» ملخّص فقط؛ السبب الحقيقي في سطور تبدأ بـ `e:` (أخطاء مترجم Kotlin) تظهر **قبل** هذه الرسالة في سجل خطوة البناء.
- على GitHub: افتح التشغيل الفاشل ثم **Summary**؛ ستجد قسم «Kotlin / Gradle errors» جاهزاً للنسخ. كما يُرفع السجل كاملاً باسم **build-log** ضمن Artifacts.
- في Android Studio: افتح تبويب **Build** وانسخ السطور الحمراء.
أرسل لي تلك السطور وسأصلح السبب مباشرة.

## أول تشغيل
- يظهر في الصفحة الرئيسية «جارٍ تجهيز محرّك التنزيل» لمدة 20 إلى 60 ثانية **في أول مرة فقط** (فك ضغط FFmpeg وتحميل yt-dlp)، ثم يصبح الإقلاع سريعاً.
- اسمح للتطبيق بالإشعارات حتى يظهر شريط التقدم في الخلفية.
- حجم الـ APK نحو 60 MB لأنه يحمل Python وFFmpeg وQuickJS.

## الاستخدام
1. ألصق الرابط (أو شاركه من التطبيق الآخر) واضغط **تحليل الرابط**.
2. اختر **فيديو** أو **صوت**، ثم الجودة (وللقوائم اختر المقاطع).
3. اضغط **تحميل** وتابع التقدم من تبويب **التنزيلات** (إيقاف مؤقت، استئناف، إلغاء).

**من المتصفح:** افتح تبويب **المتصفح** وتصفّح أي موقع وشغّل الفيديو، فيظهر زر **تحميل الفيديو**؛ اضغطه، اختر الجودة، ثم **تحميل**. وللمحتوى الذي يتطلب حساباً سجّل الدخول من المتصفح أولاً. ومن قائمة ⋮ تجد التبويب الجديد والإشارات المرجعية والسجل والبحث في الصفحة وموقع سطح المكتب.

## ملاحظات وحدود يجب أن تعرفها
- **الكوكيز:** إنستغرام وفيسبوك والمقاطع الخاصة أو المقيّدة بالعمر قد تطلب تسجيل الدخول؛ صدّر `cookies.txt` من متصفحك واستورده من الإعدادات.
- **مواقع صعبة:** بعض المواقع (مثل تيك توك وأحياناً إنستغرام) تحجب الطلبات غير الصادرة من متصفح حقيقي، وخاصية «انتحال المتصفح» غير مضمّنة هنا.
- **يوتيوب يتغيّر باستمرار:** إن توقف أحد المواقع فاضغط «تحديث yt-dlp الآن» وجرّب قناة **Nightly** (فيها أحدث الإصلاحات).
- **المحتوى المحمي (DRM)** مثل نتفليكس غير مدعوم.
- **«أي فيديو» لها حدود:** إن كان المشغّل يبثّ عبر `blob` بقطع مشفّرة أو بروابط قصيرة العمر، والموقع غير مدعوم في yt-dlp ولا يظهر له ملف أو بثّ مباشر في الشبكة، فلن يمكن تنزيله. والمواقع التي تحجب الطلبات الخارجة عن المتصفح قد ترفض التنزيل.
- يحتاج المتصفح إلى **Android System WebView** (موجود في كل الأجهزة العادية). حاجب الإعلانات بسيط: يمنع نحو 80 نطاقاً معروفاً للإعلانات والتتبع على مستوى الشبكة (ويمكن إيقافه من الإعدادات)، فهو لا يزيل كل الإعلانات ولا يحجب ما يُبثّ من خادم الفيديو نفسه. النوافذ المنبثقة محظورة، وروابط التطبيقات (`intent:` وغيرها) مُتجاهَلة.
- كوكيز المتصفح تُرسل فقط للموقع الذي تحمّل منه، وتُحذف نسخها المؤقتة بعد كل تنزيل، ويمكنك إيقاف ذلك من الإعدادات أو مسح بيانات التصفح.
- يتطلب أندرويد 8.0 فما فوق ومعالجاً 64-بت. مكتبات FFmpeg المرفقة من الإصدار 0.17.2 غير مهيّأة لأجهزة ذاكرة الصفحة 16KB (نادرة حالياً)، وقد لا يعمل الدمج والتحويل عليها حتى تُحدَّث تلك الاعتمادية.

## حالة الاختبار (بصراحة)
- **اختُبر فعلياً:** طبقة Python بالكامل مع yt-dlp الحقيقي (إصدار 2026.08.19): الإقلاع، استخراج المعلومات، التقدم والسرعة، الإيقاف والاستئناف (مطابقة بايتاً ببايت)، دمج مسارَي فيديو وصوت بـ FFmpeg، تحويل MP3، رسائل الأخطاء، وتحديث yt-dlp من قناة Nightly مع التحقق من SHA-256 والرجوع للنسخة السابقة. شغّلها بنفسك: `python tools/engine_selftest.py`.
- **تُرجم فعلياً:** كل كود Kotlin غير المرتبط بـ Compose (المحرّك، الطابور، الحفظ، الخدمة، الإشعارات، الـ ViewModel، ومتحكّم المتصفح وتبويباته ومخزنه — 151 صنفاً) بمترجم Kotlin 2.1.21 مقابل `android.jar` الخاص بـ API 35 دون أخطاء.
- **اختُبر فعلياً للمتصفح:** 72 فحصاً لمنطق العناوين ومحركات البحث وتصنيف روابط الوسائط وقواعد صفحات الفيديو وحاجب الإعلانات والاقتراحات (على JVM)، و15 فحصاً لسكربت الكشف نفسه داخل محرّك JavaScript مع محاكاة لأحداث التشغيل، ووصول Referer وUser-Agent والكوكيز إلى الخادم عبر yt-dlp، وقبول yt-dlp لملف الكوكيز الذي تولّده شيفرة Kotlin.
- **لم يُختبر في بيئتي:** بناء Gradle الكامل (لا يتوفر Android SDK هناك) والتشغيل على هاتف حقيقي، وتشغيل WebView فعلياً (كشف الفيديو داخل صفحات حقيقية، التبويبات، ملء الشاشة، صورة داخل صورة). وواجهة Compose (ومنها شاشة المتصفح ومبدّل التبويبات) فُحصت بفاحص ثابت يقارن الاستيرادات وأسماء المعاملات بقوائم الـ API الرسمية ويتحقق من النصوص العربية والإنجليزية، لكنها لم تُترجَم. إن ظهر أي خطأ عند أول بناء فأرسل لي نصه وسأصلحه.

## التخصيص
- **اسم التطبيق:** `app/src/main/res/values/strings.xml` و `values-ar/strings.xml` (المفتاح `app_name`).
- **المعرّف (Application ID):** `applicationId` في `app/build.gradle.kts`.
- **لغة جديدة:** أنشئ مجلد `values-xx` وانسخ إليه `strings.xml` ثم ترجمه، وأضف اللغة في `res/xml/locales_config.xml` وفي قائمة اللغات داخل `SettingsScreen.kt`.
